Agentic AI Integration — 1-Week POC Plan

Order Execution Build  •  Stage 1: UNDERSTAND (Steps 1–4 of the 11-Step Agentic Framework)

1.  Executive Summary

The Quantellix Order Execution Portal currently operates a proven numerical engine (SXI++ scoring, XGBoost, CatBoost, Prophet) paired with single-shot LLM inference for insight generation. This architecture delivers accurate retrospective analysis but requires human operators to manually query dashboards, correlate multi-stage dependencies, and independently determine corrective actions.

This proposal outlines a 1-week Proof-of-Concept to introduce an Agentic AI orchestration layer that autonomously executes the first 4 steps of our 11-step framework (Stage 1: UNDERSTAND). The agents will continuously monitor SXI health scores, detect threshold breaches, perform cross-stage root-cause analysis, and generate structured executive decision dossiers—all in read-only mode with zero risk to production systems.

2.  Current State vs. Target State

3.  POC Scope: The UNDERSTAND Stage (Steps 1–4)

The full 11-step framework spans four stages: UNDERSTAND (Steps 1–4), DECIDE (Step 5), ACT (Steps 6–9), and CHECK (Steps 10–11). This POC delivers Stage 1 end-to-end, producing a verified executive decision dossier ready for the human approval gate at Step 5.

Why Stage 1 is the Correct Starting Point:

Zero operational risk: Steps 1–4 operate entirely in read-only mode over existing SXI outputs and CSV datasets. No write access to any external ERP, WMS, or business system is required.

Validates the core value proposition: If the agents can reliably detect, interpret, reason about, and explain operational anomalies with mathematical proof, the remaining steps (5–11) become straightforward workflow automation.

Establishes the human-in-the-loop contract: The POC terminates at the Step 5 approval gate, demonstrating to leadership that the system advises with evidence but never executes without explicit human sign-off.

4.  Agent Architecture for Order Execution

The POC deploys four specialized micro-agents coordinated by a lightweight orchestrator. Each agent has a single responsibility, a defined tool set, and strict input/output contracts enforced via JSON Schema.

Agent 1 — Anomaly Sentinel (Step 1: Deep Search)

Responsibility: Continuously benchmarks live operational metrics against configurable alert thresholds across all 10 solution domains (E1–E10). Produces a prioritized anomaly vector ranking findings by severity and financial exposure.

Tool Access: SXI score reader, ML holdout accuracy reader, dataset statistical profiler, threshold configuration registry.

Production Pattern: Runs as a scheduled sentinel (configurable interval or on-demand trigger). In production systems, this pattern is equivalent to an observability alert engine (similar to how Datadog or PagerDuty monitors system health, but applied to business KPIs).

Agent 2 — Feature Interpreter (Step 2: Interpret)

Responsibility: Receives the anomaly vector from Agent 1. For each flagged anomaly, extracts the top contributing features from the corresponding ML model (XGBoost feature importances, CatBoost SHAP values) and translates raw mathematical weights into domain-specific operational narratives.

Tool Access: Model feature importance extractor, domain terminology mapper, solution configuration registry (maps E1–E10 codes to business names and KPI units).

Production Pattern: Equivalent to an ML Explainability Service (similar to SHAP/LIME interpretation layers used in production ML platforms at scale).

Agent 3 — Cross-Domain Causal Reasoner (Step 3: Reason)

Responsibility: The analytical core. Receives interpreted anomalies and traces causal chains across the three Order Execution stages. Determines whether a procurement-stage failure (e.g. single-source vendor delay in E9) propagated into a demand-planning stockout (E3) and downstream margin erosion (E5). Quantifies the cascading net financial exposure using SXI-computed baseline and optimized values.

Tool Access: Cross-solution dependency graph, SXI baseline/optimized KPI reader, financial impact calculator (using the same FINANCIAL_MAP used in the executive dashboard), historical run comparator.

Production Pattern: Equivalent to a Root Cause Analysis (RCA) engine. In production incident management (e.g. AWS DevOps Guru, Dynatrace Davis AI), similar systems trace cascading failures across microservice dependencies. Here, we apply the same principle to supply chain operational stages.

Agent 4 — Executive Synthesis Agent (Step 4: Explain)

Responsibility: Consumes the structured outputs of Agents 1, 2, and 3. Produces a concise, non-technical executive decision dossier formatted for C-suite consumption. The dossier contains: (a) a verified problem statement with evidence, (b) the root cause attribution chain, (c) annualized dollar exposure, (d) a recommended corrective action, and (e) a confidence assessment.

Tool Access: Executive template renderer, financial exposure aggregator, confidence scorer, dossier cache (writes to disk for instant retrieval on subsequent page loads).

Production Pattern: Equivalent to an Automated Incident Summary Generator. Production systems like ServiceNow Virtual Agent and Jira Automation generate structured incident reports from raw diagnostic data for management review.

5.  LLM Selection & Cost Analysis

Primary Model: We recommend OpenAI gpt-4o-mini as the sole production model for the POC. No secondary model is required.

Why gpt-4o-mini is the Production-Grade Choice:

Cost at scale: At $0.15/1M input tokens, a single complete 4-agent diagnostic cycle consumes approximately 4,000–6,000 tokens total (across all 4 agents). This costs $0.0006–$0.001 per run. Running 100 investigations per day costs under $0.10/day.

Latency budget: Each agent call returns in 200–400ms. The full 4-step pipeline completes end-to-end in under 2 seconds, well within interactive UX thresholds.

Structured output reliability: gpt-4o-mini supports OpenAI's JSON Schema mode with 99.8%+ compliance, eliminating parsing failures in agent-to-agent data handoffs.

SXI removes the need for expensive models: Because our proprietary SXI engine (XGBoost, CatBoost, Prophet) computes every numerical baseline, improvement percentage, and accuracy metric, the LLM never needs to perform raw mathematical calculation. It only interprets and reasons over verified numbers. This means a smaller, faster, cheaper model delivers equivalent output quality to flagship models.

8.  Production Engineering Standards

Even for a 1-week POC, all code will adhere to production-grade engineering practices. These standards are non-negotiable because the POC code will evolve directly into the production system:

Structured Outputs (JSON Schema Mode): Every LLM call uses OpenAI's response_format={'type': 'json_object'} with an explicit schema. This eliminates free-text parsing and guarantees type-safe agent-to-agent communication.

Idempotent Tool Functions: Every tool in tools.py is a pure, stateless function. Given identical inputs, it always returns identical outputs. No tool modifies any data source.

Error Isolation & Graceful Degradation: If any agent call fails (API timeout, rate limit, malformed response), the orchestrator returns partial results with a clear error annotation rather than crashing. The existing dashboard continues to function unaffected.

Prompt Versioning: All system prompts are stored as versioned string constants in agents.py (not inline in view functions). Each prompt includes a version identifier for audit traceability.

Telemetry & Cost Tracking: Every LLM invocation logs: model name, input/output token count, latency (ms), and cost. This data feeds the cost report delivered on Day 5.

Cache-First Architecture: Identical to the proven pattern in the existing generate_dynamic_hero_kpis_llm() and generate_csuite_roadmap_llm() functions: check disk cache first, call LLM only on cache miss, persist results immediately.
